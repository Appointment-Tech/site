# Notificação de leads por e-mail (Resend), sem banco de dados

O site captura dois tipos de lead (Convite e Consulta de Preço) antes de o app estar aberto ao público, então não vale montar banco/admin dedicado ainda. Decidimos: ao receber um POST, o backend dispara um e-mail via Resend (reaproveitando o domínio já verificado `send.lnascimento.com.br`, de outro projeto pessoal) para `lfsnascimento84@gmail.com`, e grava uma cópia em arquivo local (`.jsonl`) só como backup silencioso caso o envio falhe. Alternativa descartada: persistir só em arquivo e checar manualmente — rejeitada porque não dá visibilidade em tempo real, que é o que importa numa fase de captação ativa de early adopters. Trocar para banco/CRM depois é reversível: só troca o handler, a API pública (`POST /api/invites`, `POST /api/pricing-inquiries`) não muda.
